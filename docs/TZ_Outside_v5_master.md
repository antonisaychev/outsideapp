# ТЗ v5 (МАСТЕР) — «Outside», соцсеть для экспатов
## Единый документ. Заменяет v1–v4. По нему пишется код.

---

## 0. Продукт
- **Название: Outside** (рабочее)
- Аудитория: экспаты. Города на старте: **Дубай, Бали, Пхукет** (справочник, расширяемый)
- Платформы: Android + iOS (один код), скрытая админка внутри приложения
- **Языки интерфейса: русский и английский.** По умолчанию — язык устройства; переключатель в настройках. Все тексты — в словарях `ru.json` / `en.json`, в коде никаких «зашитых» строк. Справочники (города, категории) уже двуязычные (name_ru / name_en)
- Инфраструктура: домен и сервер (VPS) считаются купленными

## 1. Общие принципы
- **Гостевой режим**: просмотр всего без регистрации; любое действие с записью в БД → auth-gate (bottom sheet «Войдите, чтобы…» → Создать аккаунт / Войти). После входа отложенное действие выполняется автоматически
- Бэкенд: GET публичных данных без токена; POST/PATCH/DELETE — только с JWT (access 24 ч + refresh 30 дней)
- Все удаления — мягкие (статусы/`deleted_at`), данные из БД не стираются

## 2. Регистрация и вход
- Только **email + пароль**, без подтверждения почты. После регистрации — сразу в приложение
- **Смена email запрещена** (в настройках просто отображается)
- Пароль ≥ 8 символов, bcrypt; «Забыли пароль?» → письмо со ссылкой (SMTP — единственный внешний сервис)
- Экраны: Приветствие, Создать аккаунт, Войти, Забыли пароль, Новый пароль
```
POST /auth/register · /auth/login · /auth/refresh · /auth/forgot · /auth/reset
```

## 3. Профиль
Поля: Имя, Фамилия, Аватар, О себе (300), Город (справочник), **Пол** (муж/жен — обязателен, запрашивается при первом заполнении профиля), **Дата рождения** (в настройках профиля; обязательна для включения «Знакомств», в остальном опциональна). Пока имя пусто — показываем часть email до @.
```sql
users (
  id UUID PK, email UNIQUE, password_hash,
  first_name, last_name, avatar_url, bio VARCHAR(300),
  city_id INT REF cities, gender ENUM('male','female'),
  birth_date DATE NULL,
  lang ENUM('ru','en') DEFAULT NULL,          -- выбранный язык интерфейса
  account_type ENUM('person','business') DEFAULT 'person',
  role ENUM('user','admin') DEFAULT 'user',
  is_blocked BOOL DEFAULT false, blocked_reason VARCHAR(300),
  deleted_at TIMESTAMP NULL, created_at, last_seen_at
)
cities (id, name_ru, name_en, country_ru, country_en, is_active)  -- Дубай, Бали, Пхукет
```
Чужой профиль: шапка + кнопки по состоянию (Добавить в друзья / Заявка отправлена / Принять / ✓ Друзья; Подписаться; **Написать** — если друзья).

## 4. Настройки (шестерёнка в Профиле)
```
Редактировать профиль (имя, фамилия, аватар, о себе, город, пол, дата рождения)
Сменить пароль
Email: user@mail.com  (только просмотр)
Язык: Русский / English
Знакомства: участвовать [toggle] · Моя анкета
Заблокированные пользователи
Условия · Политика · Версия
Выйти · Удалить аккаунт (двойное подтверждение, ввод пароля)
```
Удаление аккаунта: soft-delete, его карточки сервисов скрываются.

## 5. Друзья (модель Facebook)
Заявка → принять/отклонить (отправителю про отказ не сообщаем) · удаление из друзей · блокировка друг друга. Таблица `friendships(requester_id, addressee_id, status pending/accepted/declined/blocked)`. Рекомендации: общие друзья + тот же город. Принятие дружбы = автоматические взаимные подписки.

## 6. Подписки (модель Instagram)
Односторонние, без подтверждения. `follows(follower_id, followee_id)`. Основной сценарий — бизнес-аккаунты и авторы.

## 7. Знакомства (свайпы)
- **Без ограничения 18+**, но для включения раздела обязательны: имя, аватар, пол, дата рождения (возраст показывается на карточке)
- Opt-in: по умолчанию юзер в колоде не показывается; включил — показываем его и показываем ему
- Колода: тот же город, активные, не свайпнутые, взаимный фильтр «кого показывать»; pass возвращается через 30 дней; лимит 100 лайков/сутки
- Взаимный лайк = **мэтч → автодружба** + экран «Это мэтч! 🎉» с кнопкой **«Написать сообщение»** (открывает чат)
```sql
dating_profiles (user_id PK, is_active BOOL, looking_for ENUM(friends,dating,networking,any),
                 show_gender ENUM(male,female,any))
swipes (swiper_id, target_id, direction like/pass, created_at, PK(swiper,target))
matches (id, user_a, user_b, created_at)
```

## 8. Сервисы (рекомендации бизнесов)
- Плитка карточек по городу (из профиля юзера; переключатель города; гость выбирает вручную). Рекомендуем организации, не людей
- Табы: **«Рекомендовано»** (сортировка по лайкам ↓) и **«На проверке»** (прогресс «18/30»)
- Форма «+»: Название*, Категория*, Фото*, Описание* (500), Ссылка на сервис, Гео-ссылка, Город* (по умолчанию свой). Проверка на дубли по названию
- Порог: 30 зачётных лайков = лайки юзеров с тем же городом на момент лайка (город фиксируется в записи); свой лайк автора не в счёт; статус recommended не откатывается; после публикации лайкают все, рейтинг = общее число лайков. Порог в конфиге
- **Редактирование карточек — только админ** (автор после отправки менять не может, любые правки через админа)
- Сетевые сервисы в двух городах = **две отдельные карточки**
- «Пожаловаться» на карточке → в админку
```sql
service_categories (id, name_ru, name_en, icon, sort)  -- Медицина, Еда, Красота, Транспорт,
   -- Жильё, Дети и школы, Спорт, Документы и визы, Коворкинги, Развлечения, Другое
services (id, author_id, city_id, category_id, title, description, photo_url,
  website_url, map_url, status pending/recommended/hidden,
  likes_count INT, confirm_count INT, approved_by_admin BOOL, created_at, published_at)
service_likes (service_id, user_id, user_city_id, created_at, PK(service,user))
service_reports (id, service_id, user_id, reason, created_at)
```

## 9. Сообщения (чат) — НОВЫЙ МОДУЛЬ
- Личные чаты 1-на-1, **только текст** (до 2000 симв.), без групп, фото и голосовых в MVP
- **Кто может писать кому: только друзья** (мэтч = дружба, значит и мэтчи). Кнопка «Написать» — на профиле друга и на экране мэтча. [решение, см. вопрос ниже]
- Экран «Сообщения»: список диалогов (аватар, имя, последнее сообщение, время, бейдж непрочитанных), сортировка по последнему сообщению
- Экран диалога: история (пагинация вверх), поле ввода, статусы ✓ отправлено / ✓✓ прочитано, «был(а) в сети…» из last_seen_at
- Реалтайм: **WebSocket** (свой, на том же сервере). Оффлайн-получателю сообщение ляжет в БД и придёт при следующем подключении. Push — в след. версии
- Блокировка между юзерами закрывает чат («Вы не можете писать этому пользователю»)
```sql
conversations (id UUID PK, user_a UUID, user_b UUID, created_at,
               last_message_at, UNIQUE(user_a,user_b))   -- user_a < user_b
messages (id UUID PK, conversation_id REF, sender_id REF,
          text VARCHAR(2000), created_at, read_at TIMESTAMP NULL)
```
```
GET  /chats                       -- список диалогов + unread
GET  /chats/:id/messages?before=  -- история
POST /chats                       { user_id }  -- найти/создать диалог
POST /chats/:id/messages          { text }
POST /chats/:id/read
WS   /ws  события: message.new, message.read, user.online
```

## 10. Уведомления
Колокольчик + бейдж. Типы: заявка в друзья (Принять/Отклонить в строке), заявка принята, новый подписчик, карточка в «Рекомендовано», мэтч. Новые сообщения — бейджем на вкладке «Сообщения», не в колокольчике. Пока без push.

## 11. Блокировка пользователя (админом)
- Заблокированный при входе видит экран: **«Ваш аккаунт заблокирован»** + причина + контакт поддержки; все запросы его токеном → 403
- **Все его карточки сервисов скрываются** (status → hidden), профиль исчезает из поиска, колоды, списков; его чаты закрываются
- Разблокировка возвращает профиль; карточки восстанавливает админ вручную при необходимости

## 12. Админка — скрытый раздел в приложении
- Виден только `role='admin'`: в Настройках появляется пункт «Администрирование». Назначение админа — вручную в БД
- Экраны: Пользователи (поиск, Заблокировать с причиной / Разблокировать) · Карточки (фильтр по статусу/городу; **Одобрить досрочно** pending→recommended; **Скрыть**; **Редактировать любые поля** карточки) · Жалобы (список со ссылками)
```
GET /admin/users · POST /admin/users/:id/block|unblock
GET /admin/services · POST /admin/services/:id/approve|hide · PATCH /admin/services/:id
GET /admin/reports
```
