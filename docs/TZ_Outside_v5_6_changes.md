# ТЗ v5.6 — Правки продукта (дополнение к v5, v5.3, v5.5)

## 1. Никнеймы и ссылки на профиль (НОВОЕ)
- На этапе регистрации пользователь ВРУЧНУЮ выбирает никнейм (поле на экране регистрации)
- Правила: латинские буквы и нижние подчёркивания, до 30 символов (мин. 3), уникальный,
  регистронезависимый (хранится в нижнем регистре). Цифры и другие символы запрещены
- Проверка занятости в реальном времени («занято / свободно»)
- Ссылка на профиль: https://[ДОМЕН]/@nickname — открывает профиль (веб-заглушка → приложение)
- В профилях (своём и чужих) — @nickname под именем + кнопка «копировать ссылку»
```sql
users: + username VARCHAR(30) UNIQUE NOT NULL   -- ^[a-z_]{3,30}$
GET /users/check-username?u=...
```

## 2. Избранное (сохранение сервисов) (НОВОЕ)
- Сердечко теперь = «сохранить в избранное» (а не лайк): крупная иконка справа вверху
  на карточке сервиса (плитка и детальный экран)
- Вход в «Избранное» — сердечко справа вверху раздела «Сервисы»; отдельный экран со списком
- Лайк-подтверждение теперь — «палец вверх» 👍 (иконка ThumbsUp) везде, где были лайки
```sql
service_favorites (user_id, service_id, created_at, PK(user_id,service_id))
POST/DELETE /services/:id/favorite · GET /me/favorites
```

## 3. Админка: расширение
- **Редактирование сервиса**: из списка сервисов админ открывает карточку в форме
  (как при создании), меняет любые поля/фото и сохраняет (PATCH /admin/services/:id)
- **Фильтры (категории)**: новый таб «Фильтры» — админ создаёт и удаляет категории;
  они появляются в выборе на форме создания сервиса и в чипах раздела
```
POST   /admin/categories {name_ru,name_en}   DELETE /admin/categories/:id
```
  Удаление категории возможно, только если нет активных сервисов с ней (иначе — ошибка)
- **«Принять меры» в жалобе** — переводит админа в карточку сервиса (или профиль
  пользователя, если жалоба на пользователя) для проверки и действий

## 4. Выбор категории при создании сервиса
Отдельная шторка выбора категории (радио-список) — открывается тапом по чипу категории
на форме «Новая рекомендация». Экран 40 в Figma.

## 8. Создание фильтра (категории) админом — диалог
Кнопка «Добавить» на табе «Фильтры» открывает диалог «Новый фильтр»:
Название (рус) + Name (eng) — оба обязательны, т.к. приложение двуязычное;
кнопки Создать/Отмена. Иконок у фильтров НЕТ (поле icon удалено из service_categories).
Экран 44 в Figma.

## 8.1 Терминология: «Место», не «Город»
Во всех текстах интерфейса слово «Город» заменено на «Место» (переключатель места
в Сервисах, «Место: Бали» на формах, строка «Место» в редактировании профиля).
В БД таблица остаётся cities — это внутреннее имя, пользователю не видно.
Символ «⌄» из текстов удалён; стрелка переключателя — SVG-шеврон.

## 9. Правило переноса текста (дизайн + код)
- Поля ввода и текстовые блоки: если текст не помещается в одну строку — перенос на
  следующую с расширением блока по высоте (Input-компоненты кита переведены на
  авто-высоту с minHeight 56)
- Исключение — превью в списках (последнее сообщение в диалогах и т.п.): одна строка
  с многоточием в конце
